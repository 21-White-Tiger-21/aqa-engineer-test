# API-тесты сервиса управления пользовательской сессией

Тестовое приложение проверяется как black-box: тесты запускают предоставленный Spring Boot JAR,
поднимают управляемую заглушку внешнего сервиса на WireMock и работают с публичным API через HTTP.

## Что проверяется

| Область | Сценарии |
|---|---|
| Полный пользовательский путь | успешные `LOGIN -> ACTION -> LOGOUT` |
| Управление сессией | действие до входа и после выхода, повторный вход, выход неизвестного пользователя, независимость пользователей |
| Внешний сервис | успешные и ошибочные ответы `/auth` и `/doAction`, точное число и содержимое исходящих запросов |
| Валидация | длина и алфавит токена, пустые/отсутствующие параметры, неизвестное действие |
| Безопасность | отсутствующий и неверный `X-Api-Key` |

Названия тестов, шаги и описания Allure сформулированы на языке пользовательских сценариев, чтобы отчёт
был понятен не только разработчику.

## Требования

- Java 17+
- Maven 3.8+
- свободные порты `8080` (приложение) и `8888` (WireMock)
- файл `app/internal-0.0.1-SNAPSHOT.jar`

## Запуск

```bash
mvn clean test
```

Тесты сами запускают и останавливают приложение и WireMock. Параллельный запуск намеренно отключён:
приложение хранит сессии в памяти и использует фиксированные порты.

## Отчёт Allure

```bash
mvn allure:serve
```

Результаты формируются в `target/allure-results`.

Для каждой HTTP-операции Allure прикладывает запрос и ответ. Лог запущенного тестового приложения
сохраняется в `target/application-under-test.log`, что упрощает разбор неуспешного прогона.

## Принятые решения

- Для каждого сценария создаётся уникальный валидный токен, поэтому тесты не зависят друг от друга.
- Проверяется не только ответ приложения, но и отсутствие нежелательных вызовов внешнего сервиса.
- При временной ошибке `/doAction` отдельно проверяется, что ранее созданная сессия остаётся рабочей.
- Статус HTTP и бизнес-результат проверяются раздельно.

## Структура

- `client` - HTTP-клиент тестируемого сервиса;
- `model` - модели API;
- `support` - запуск приложения и генерация тестовых токенов;
- `tests` - сценарии сессии и валидации запроса.
