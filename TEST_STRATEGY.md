# Тестовая стратегия

## Цель

Подтвердить, что сервис корректно управляет жизненным циклом пользовательской сессии и безопасно
взаимодействует с внешним сервисом при успешных и ошибочных ответах.

## Уровень тестирования

Black-box API-тесты. Внутренняя реализация и классы приложения не используются. Единственная тестовая
граница - публичный HTTP API; внешний сервис заменён WireMock.

## Риски и приоритеты

1. Пользователь выполняет действие без успешной аутентификации.
2. Неуспешная аутентификация ошибочно создаёт сессию.
3. Выход не удаляет сессию.
4. Сессии разных пользователей влияют друг на друга.
5. Сервис выполняет лишние вызовы внешней системы.
6. Некорректные параметры или API-ключ принимаются приложением.

## Наблюдаемая HTTP-семантика

| Ситуация | Ожидаемый статус |
|---|---:|
| Успешная операция | 200 |
| Ошибка валидации запроса | 400 |
| Нет активной сессии | 403 |
| Токен уже вошёл в систему | 409 |
| Внешний сервис вернул ошибку | 500 |

Во всех бизнес-ошибках дополнительно проверяется JSON с `result = ERROR` и непустым `message`.

## Изоляция

- каждый тест получает новый 32-символьный токен из `A-Z0-9`;
- WireMock очищается перед каждым тестом;
- параллельное выполнение отключено из-за фиксированных портов и общего хранилища приложения;
- приложение запускается и завершается тестовым окружением автоматически.

## Что не покрыто

- производительность и нагрузка;
- длительное хранение сессий после перезапуска (по условию хранилище внутреннее);
- TLS, инфраструктура и сетевые сбои ниже HTTP-уровня;
- безопасность за пределами проверки статического API-ключа.
